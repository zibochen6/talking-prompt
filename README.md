# 同频 · 局域网提词器

Mac 和 iPhone 共用一份提词文稿。纯黑背景、白色大字，播放、暂停、速度与阅读位置实时同步，字号各端独立。

## 安装与启动

1. 从 [GitHub Releases](https://github.com/zibochen6/talking-prompt/releases/latest) 下载与你的 Mac 芯片相符的 DMG：`arm64` 对应 Apple 芯片，`x64` 对应 Intel 芯片。
2. 打开 DMG，将「同频提词器」拖入「应用程序」，然后启动。安装包目前没有 Developer ID 签名或 Apple 公证；首次打开如被 macOS 阻止，可在「系统设置 → 隐私与安全性」查看并允许打开。
3. 在 Mac App 中点击 **编辑文稿**，输入或粘贴内容，再点 **应用文稿**。
4. 让 iPhone 和 Mac 连接同一个 Wi-Fi，点击 **连接设备**，用 iPhone 相机扫码，在 Safari 打开。
5. 在任一端开始、暂停或调整速度；字号由每台设备单独调整。

安装包自带所需运行环境，日常提词不需要互联网或安装 Node.js。请保持 Mac 不休眠；关闭窗口后局域网服务继续运行，使用菜单「同频 → 退出同频」结束服务。

应用启动后和运行期间会检查 GitHub Release，也可以在菜单「同频 → 检查更新」手动检查。有新版本时，点击通知或菜单中的版本入口打开下载页，下载并手动安装；网络不可用时本地使用不受影响。更新会保留应用数据。

### 从旧版迁移

首次启动时，应用会查找原项目目录中的 `.local-data/session.json`，将其复制到统一的应用数据目录，原文件保留作为备份。已有应用数据不会被覆盖；若迁移失败会提示原因并保留原文件。原来的 **启动提词器.command** 也使用同一个应用数据目录；请不要同时运行两种启动方式。

旧项目位于其他路径时，可先通过该项目内的 `启动提词器.command` 启动一次，完成迁移后退出，再启动 Mac App。字号与未应用的草稿存放在各自的浏览器中，Mac App 是独立的浏览器环境，首次使用时可重新设置；iPhone 的浏览器数据仍保留在手机上。

旧版命令启动方式首次准备依赖仍需要联网，并需要 Node.js 22.12 或更新版本。

## 操作说明

- **播放／暂停**：任意一端均可控制；电脑在阅读区按空格也能切换。编辑文字或操作滑块时，空格不会触发播放。
- **回到开头**：所有设备暂停，阅读位置归零。
- **调整进度**：拖动进度条，或在阅读区滚动／上下拖动。所有设备会暂停并跟随到新位置。
- **沉浸阅读**：隐藏工具栏；点击阅读区、右上角退出按钮，或在电脑按 Escape 恢复。
- **手机横屏**：自动切换为阅读优先布局，隐藏页头和附加信息，底部仅保留一行播放、进度、阅读设置和沉浸按钮。点击滑块图标的 **阅读设置** 调整速度、字号，也可打开编辑文稿和连接设备。首次以横屏打开时默认使用 36px 字号；已经设置过的字号会保留。
- **文稿编辑**：草稿自动保存在编辑设备的浏览器中。点击应用才会替换共享文稿，所有设备暂停并回到开头。若另一端先更新了文稿，会提示载入最新文稿，避免旧草稿误覆盖。
- **断线与后台**：设备断线时冻结阅读并禁用共享控制。重新连接或返回前台后，跟随 Mac 上的最新状态；其他在线设备仍可继续提词。
- **刷新与重启**：当前文稿、速度、阅读位置保存在 Mac，重启后恢复且保持暂停。字号保存在每台设备的浏览器；清除网站数据后会恢复默认值。
- **读到末尾**：自动暂停；再次播放会从开头开始。

文稿支持最多 10 万个 UTF-16 单元（常见中文约 10 万字，部分表情占两个单元）。提词按 Unicode 字符位置推进，包含标点、空格与换行。不同屏幕不会同步像素滚动距离，而是同步读到的文字位置。

## 连接不上时

- 手机必须使用网页展示的局域网地址，如 `http://192.168.1.10:3210`，不能使用 `localhost`。
- 如果 Mac 提示是否允许网络连接，请允许该应用的局域网入站连接。
- 若二维码中地址不能访问，尝试连接面板的其他网络地址。VPN、访客 Wi-Fi 或路由器的设备隔离功能可能阻止互相访问。
- 网络发生变化后，重新打开连接面板获取新地址并扫码。
- 默认端口为 `3210`。如果提示端口占用，先关闭之前打开的提词器启动窗口。开发者也可以用 `PORT=3211 npm start` 指定其他端口。
- 若系统阻止打开 `.command` 文件，可在 Finder 中右键该文件并选择“打开”。
- 若无法保存，页面会显示提示。检查 Mac 的磁盘空间与目录权限，并及时保留文稿副本。

此版本免登录，同一局域网中能访问地址的设备都可查看和控制文稿，适合自己的可信网络；无需云服务和账户。

## 本地数据

Mac 服务端数据位于 `~/Library/Application Support/Tongpin/session.json`，不纳入版本控制。旧目录 `.local-data/session.json` 在迁移后保留为备份，后续文稿请以应用数据目录为准。播放期间约每秒保存一次，操作和正常停止服务时也会保存。异常断电最多可能损失最近约一秒的播放进度。损坏的数据文件会原样备份到同目录的 `session.json.backup-*`，页面会提示重新应用文稿。

## 开发与检查

```sh
npm ci
npm run dev    # 局域网开发服务，默认端口 3210
npm run build  # TypeScript 检查并构建
npm start      # 运行已构建版本
npm test       # 状态与真实 WebSocket 服务测试
npm run launch # 与旧版双击启动相同的准备与启动流程
npm run desktop # 从源码运行 Mac App
npm run dist:mac # 构建 Mac DMG，输出到 release/
```

环境变量：旧版服务可用 `PORT` 设置端口；`PROMPT_DATA_DIR` 指定独立数据目录（指定时跳过自动迁移）；`PROMPT_LEGACY_DATA_DIR` 指定旧数据目录；`PROMPT_NO_OPEN=1` 禁止旧版启动时自动打开浏览器。Mac App 使用端口 3210。

技术结构：React + TypeScript + Vite 前端，Node.js HTTP 服务和 WebSocket 同步。`/api/connection` 提供局域网连接信息；`/sync` 接收操作并广播状态。所有资源本地提供，无外部字体、CDN 或统计请求。

## 发布版本

更新 `package.json` 与锁文件中的版本号，提交后推送与版本一致的标签（如 `v1.0.0`）。GitHub Actions 会为 arm64 和 x64 构建 DMG，全部成功后发布带 SHA-256 校验文件的 GitHub Release。当前发布配置刻意不使用签名或公证；取得 Developer ID 后可配置签名、公证和标准自动安装更新。
